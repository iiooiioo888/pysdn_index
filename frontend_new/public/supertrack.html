SIGNAL TRACKING

SuperTrack 全網追蹤模組

實體、內容與提示詞的一條龍資料閉環

概述

SuperTrack 作為 SuperForge 的擴展外掛，專注於「實體→內容→提示詞」的資料閉環。

系統分層（思維導圖）

目標、擷取、分析到輸出；與 /docs/supertrack 一致。

🔑 核心組件

  • EntityResolver：統一實體模型與解析
  • CrossPlatformCrawl：模擬人工採集引擎
  • BehaviorSim：行為模擬（捲動／停留／隨機間隔）
  • TimeSeriesDB：時序資料儲存（TimescaleDB）
  • AlertEngine：預警引擎
  • PromptLink：與 SuperForge 提示詞庫聯動

架構

[SuperTrack 抓取] → [清洗 + 實體解析] → [時序儲存 + 預警]
                          ↓
[高品質內容] → [LLM 結構化] → [寫入 SuperForge.prompts]
                          ↓
[使用者檢索] → 「找某類風格 Prompt」→ 關聯來源帳號 + 互動資料參考

端到端資料流

爬蟲、合併、分析、異常與對三模組輸出。

追蹤維度

追蹤對象類型 追蹤重點 輸出應用
網紅／KOL 發文頻率、互動率、標籤演化、合作品牌 風格 Prompt 庫、趨勢預警
店舖／品牌 產品曝光、使用者評論情感、促銷活動 商業提示詞模板、競品分析
法人／企業 新聞提及、輿情情感、關聯人物 合規監控、風險提示
名人／公眾人物 話題熱度、跨平台聲量、形象關鍵詞 創意靈感召回、IP 聯動建議

技術棧

  • 儲存：PostgreSQL + TimescaleDB + pgvector
  • 採集：Playwright + Python
  • 部署：Windows 服務 + NAS 本機儲存 + Supabase

安裝

pip install -r requirements.txt

使用範例

from supertrack.core import EntityResolver, CrossPlatformCrawl
from supertrack.engine import AlertEngine, PromptLink

# Init
resolver = EntityResolver()
crawler = CrossPlatformCrawl()
alert_engine = AlertEngine()
prompt_link = PromptLink()

entity_id = resolver.add_entity(
    name="KOL name",
    entity_type="kol",
    platform_ids={"xiaohongshu": "12345", "instagram": "@user"},
    tags=["fashion", "cyberpunk"],
    region="TW"
)

crawler.start_tracking(entity_id)

alert_engine.set_threshold(entity_id, metric="follower_growth", threshold=0.1)

工程架構與調研參考

本段與 SPA 文件頁 /docs/supertrack#engineering 同向維護，不再自 SuperTrack_Documentation.md 載入。

統一調度層與資料架構（概念）

  • 任務產生：依追蹤目標與頻率產生抓取任務。
  • 佇列與分發：優先級佇列；工作節點拉取。
  • 執行與節流：行為模式、瀏覽器或 HTTP adapter；令牌桶。
  • Adapter 層：各平台可替換；調度層處理統一 DTO。
  • 資料流：原始資料 → 結構化 → 分析與下游模組。
